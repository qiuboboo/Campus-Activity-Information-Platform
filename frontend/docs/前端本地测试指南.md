# 前端本地测试指南

最后更新：2026-07-14。

## 启动

### 模式一：只看前端页面（使用 Mock）

```bash
powershell -ExecutionPolicy Bypass -File scripts/start-dev.ps1
```

Mock 服务监听 `5000`，Vite 监听 `3000`。请求通过 `/api` 代理转发；不要再使用已删除的 `mock-server.js`，也不要使用旧路由 `/login` 或 `/activities/:id` 查看详情。

### 模式二：Docker 启动真实后端，本机启动前端

不要同时启动 Mock 和真实后端，因为它们都会占用 `5000` 端口。

```bash
powershell -ExecutionPolicy Bypass -File scripts/start-dev.ps1 -Mode docker

# 首次启动或清空数据库后，可以加：
powershell -ExecutionPolicy Bypass -File scripts/start-dev.ps1 -Mode docker -InitDb -SeedDemo
```

访问 `http://127.0.0.1:3000`。前端会通过 Vite 代理把 `/api` 请求转发到 `http://127.0.0.1:5000`。
脚本的 Docker 模式默认只启动 `postgres`、`redis` 和 `api`，不启动 Celery worker；本地浏览和基础联调不依赖 worker。

如果 Docker 构建时卡在拉取 `python:3.12-slim`，说明 Docker Hub 网络不可用或很慢；可以先只启动数据库和 Redis：

```bash
cd backend
docker compose up -d postgres redis
```

然后在本机 Python 环境运行后端，或配置 Docker Desktop 镜像加速后重新执行 `docker compose up -d --build`。

停止脚本启动的本机前端和 Mock：

```bash
powershell -ExecutionPolicy Bypass -File scripts/start-dev.ps1 -Stop
```

## 自动化检查

```bash
npm run verify
```

它会运行类型检查与生产构建、Vitest 单元测试、Playwright 端到端测试。端到端测试会自动启动 Mock 与 Vite 服务。

## 手动验收

1. 访客访问首页，执行搜索、分类筛选和详情查看。
2. 使用 `zhangsan / 123456` 登录，访问“我的发布”，上传一份允许类型的附件（≤10 MB），创建活动并提交审核；确认非法格式和失败上传有反馈与重试。
3. 清除登录状态后使用 `admin / admin123456` 登录，在审核队列批准或驳回活动。
4. 在活动详情验证收藏、加入日历、ICS 导出、订阅关联节点；在个人中心确认通知已读状态。
5. 在 `/activities` 和 `/search` 切换排序，确认 URL 与结果同步；在被驳回活动中确认显示审核反馈。
6. 在 375px、768px、1024px 和桌面宽度检查无横向溢出，并用 Tab 键访问主要按钮、日历活动和通知。

## 后端联调

1. 停止 Mock，启动后端服务。
2. 复制 `.env.example` 为 `.env.local`，按部署方式设置 `VITE_API_BASE_URL`；同源反向代理通常保持 `/api`。
3. 保持前端 `Activity` 与 `/activities` 格式，由网关/API 适配层转换后端资源。
4. 按 [后端联调清单](frontend-plan/BACKEND_INTEGRATION_CHECKLIST.md) 验证认证、时区、分页、错误码、下载和角色边界。

后端总文档未冻结的报名、独立收藏、资料更新和密码重置能力，不应在联调中被误判为后端已实现；其前端 Mock 流程只用于页面验收。
