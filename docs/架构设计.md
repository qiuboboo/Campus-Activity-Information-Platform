# 校园活动信息平台 — 架构设计

## 1. 系统定位

面向校内官方大型活动的信息平台。将分散的活动信息采集、结构化、关联展示，并集成 AI 能力实现信息提取和智能搜索。

核心设计原则：**AI 增强，而非 AI 依赖**。所有 AI 功能均有对应的非 AI 兜底实现。

## 2. 技术选型

| 层次 | 技术 | 用途 |
|------|------|------|
| Web 框架 | Flask | REST API |
| WSGI | Gunicorn | 生产环境 |
| 数据库 | PostgreSQL + pgvector | 业务数据 + 向量检索 |
| ORM | SQLAlchemy | 数据访问 |
| 缓存/队列 | Redis | Celery Broker + 结果缓存 + 会话 |
| 异步任务 | Celery + Celery Beat | 爬虫、AI 调用、向量生成 |
| 认证 | JWT + 图形验证码 + 邮箱验证码 | 无状态鉴权 |
| AI | OpenAI 兼容 API | 语义提取、摘要、搜索 |
| 搜索 | SearXNG + 搜狗微信 | 多引擎外部搜索 |
| MCP | mcp (Python SDK) | 连接外部 MCP 服务器 |
| 爬虫 | requests + BeautifulSoup | 网页抓取 |
| 前端 | Vue 3 + Element Plus + Vite | SPA |
| 部署 | Docker Compose + Nginx | 容器化部署 |

## 3. 系统架构

```
Nginx (:80) → Flask + Gunicorn (:5000)
    ├── PostgreSQL + pgvector
    ├── Redis
    ├── Celery Worker (crawl / ai / index 三个队列)
    ├── Celery Beat (定时调度)
    ├── LLM API (DeepSeek / OpenAI / Copilot Pro)
    ├── SearXNG (Google / Bing / DuckDuckGo / 百度)
    └── MCP Server (小红书等扩展数据源)
```

分层结构：**API 层 → Service 层 → Tasks 层 → Data 层 → External 层**

## 4. 模块设计

| 模块 | 职责 | 关键实现 |
|------|------|---------|
| 认证权限 | 注册/登录、JWT、RBAC | 图形验证码 + 邮箱验证码 + 限流 |
| 海报管理 | 创建/编辑/审核/发布 | 草稿→审核→发布流程、HTML 海报生成 |
| 知识库 | 知识节点管理 + 海报关联 | 规则匹配 + 字典标准化 + AI 增强 |
| 关联展示 | 两级超链接模型 | 一级：海报→节点；二级：节点→扩展内容 |
| 搜索 | 内部检索 + 外部搜索 | 全文 LIKE + 向量余弦相似度 + SearXNG 多引擎 |
| 数据源爬虫 | 外部网页抓取 | SSRF 防护、域名白名单、频率控制 |
| AI/MCP 集成 | LLM 调用 + MCP 客户端 | 多模型 profile 切换、自动降级 |
| 订阅通知 | 节点/关键词订阅 | 发布时自动匹配、平台内通知 |
| 个人日历 | 活动收藏 + .ics 导出 | 一键添加到系统日历 |
| 质量去重 | 质量评分 + 重复检测 | 哈希指纹 + 字段组合去重 |
| 审计日志 | 操作追踪 | 结构化审计记录、可查询 |

## 5. 数据库核心表

| 表 | 用途 |
|---|---|
| `users` | 用户与角色 (viewer / publisher / admin) |
| `posters` | 活动海报，含结构化字段、质量评分、向量嵌入 |
| `knowledge_nodes` | 知识节点 (时间、地点、主办方、主题等) |
| `poster_node` | 海报-节点多对多关联 |
| `poster_links` | 海报-海报横向关联 |
| `data_sources` | 外部数据源配置 (含爬虫安全参数) |
| `crawl_logs` | 抓取日志 |
| `subscriptions` | 用户订阅 (按节点或关键词) |
| `notifications` | 平台内通知 |
| `user_calendar_events` | 用户日历收藏 |
| `dict_entries` | 受控词表 (地点/组织/主题别名标准化) |
| `audit_logs` | 审计日志 |

## 6. 核心流程

### 海报发布

```
用户提交文本 → 提取结构化字段 → 生成 HTML → 存为草稿
→ 提交审核 → 管理员审核 → 通过后匹配知识节点
→ 建立海报关联 → 发布 → 推送订阅通知
```

### 爬虫入库

```
Celery 触发 → 域名白名单校验 → GET 请求 (限速/限流)
→ BeautifulSoup 提取 → 内容清洗 (XSS/敏感信息过滤)
→ 去重检测 → 质量评分 → 创建草稿 → 审计日志
```

### 搜索

```
用户输入 → 内部: LIKE + pgvector 向量检索 → 合并排序
         → 外部: SearXNG(Google/Bing/百度) + 搜狗微信 → 标记来源
```

## 7. 部署

生产环境 Docker Compose 一键部署：

```bash
cp .env.example .env   # 配置密钥
docker compose up -d    # Flask + PostgreSQL + Redis + Celery + SearXNG + Nginx
```

推荐配置：2核4G + 50GB (课程演示) 或 4核8G + 70GB (试运行)。
