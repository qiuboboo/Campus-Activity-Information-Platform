# 服务器权限与开发账户说明

本文用于规范当前项目在服务器上的账户分工、权限边界与日常开发方式，避免因直接使用 `root` 进行开发导致权限混乱、工具受限或误操作风险增大。

## 1. 账户分工

当前服务器建议至少保留两个角色：

- `root`：系统管理员账户
- `workspace`：项目开发账户

## 2. root 负责什么

`root` 只负责系统级操作，不参与日常代码开发。

适合由 `root` 执行的操作包括：

- 安装系统软件，例如 `git`、`docker`、`nginx`
- 管理系统服务，例如 `systemctl start docker`
- 修改防火墙、端口、安全组相关配置
- 配置 Nginx 反向代理
- 配置系统级目录权限
- 创建、删除、维护普通用户

不建议由 `root` 执行的内容包括：

- 日常编写和修改项目代码
- 使用 VS Code Remote SSH 作为主开发账户
- 直接运行 Claude Code 进行开发
- 在项目目录内长期执行 `git pull`、`git commit`、`pip install`

## 3. workspace 负责什么

`workspace` 是默认开发账户，推荐所有开发相关操作都在该用户下完成。

适合由 `workspace` 执行的操作包括：

- 使用 VS Code Remote SSH 连接服务器
- 拉取和管理项目代码
- 运行 `claude`
- 创建 Python 虚拟环境
- 安装项目依赖
- 运行 Flask 后端
- 执行 `docker compose up -d --build`

## 4. 为什么不用 root 开发

不建议直接使用 `root` 进行开发，主要原因如下：

- 风险更高，误删或误改系统文件的后果更严重
- 文件所有者容易变成 `root`，导致普通用户后续无法正常编辑
- Claude Code 在 `root` 下会受到更严格的安全限制
- 远程开发工具在普通用户环境下通常更稳定

## 5. 推荐目录约定

推荐使用如下目录结构：

```text
/home/workspace/校园活动平台
```

项目代码、虚拟环境、开发配置统一放在 `workspace` 的家目录下，不要长期放在 `/root` 下。

## 6. Docker 使用建议

如果需要让 `workspace` 直接执行 Docker 命令，可将其加入 `docker` 用户组：

```bash
sudo usermod -aG docker workspace
```

执行后需要重新登录一次 SSH 会话，新的组权限才会生效。

## 7. VS Code 连接建议

本机 `~/.ssh/config` 中建议使用 `workspace` 作为默认远程用户，例如：

```sshconfig
Host aliyun-server
    HostName <your-server-ip>
    User workspace
    Port 22
```

## 8. 日常开发流程建议

推荐流程如下：

1. 使用 `workspace` 通过 VS Code Remote SSH 连接服务器
2. 进入项目目录
3. 激活 Python 虚拟环境或启动 Docker
4. 使用 Claude Code、Git、Python、Docker 进行开发
5. 仅在需要安装系统软件或调整系统配置时切换为 `root`

## 9. 一句话原则

系统级管理用 `root`，项目开发一律用 `workspace`。
