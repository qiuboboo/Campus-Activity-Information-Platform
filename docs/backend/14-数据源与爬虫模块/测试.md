# 数据源与爬虫模块测试

## 测试文件结构

| 文件 | 类型 | 测试目标 |
|------|------|----------|
| `backend/tests/test_data_sources_api.py` | 集成测试 | 数据源 CRUD、手动抓取、日志查询等 HTTP 端点 |
| `backend/tests/test_data_source_service.py` | 单元测试 | `data_source_service` 中的业务逻辑和数据库操作 |
| `backend/tests/test_security_service.py` | 单元测试 | `security_service` 中的 URL 校验、内容清洗、频率控制 |

---

## 1. `test_data_sources_api.py` -- 数据源 API 集成测试

### 测试策略

通过 Flask 测试客户端模拟 HTTP 请求，验证各端点的路由、认证、权限控制、请求体验证和响应结构。依赖 conftest 中的 fixture 创建测试数据源和认证 header。

### 依赖的 Fixture

- `client`：Flask 测试客户端
- `admin_headers`：带有 admin 角色 JWT 的请求头
- `viewer_headers`：带有 viewer 角色 JWT 的请求头
- `sample_data_source`：数据库中预先创建的数据源记录（`name="校园网通知公告"`）

### 测试类与场景

#### `TestListDataSources`

| 测试方法 | 场景 | 验证点 |
|----------|------|--------|
| `test_returns_sources` | 正常获取列表 | 200，`items` 存在且长度 >= 1 |
| `test_requires_auth` | 未携带 JWT | 401 |

#### `TestCreateDataSource`

| 测试方法 | 场景 | 验证点 |
|----------|------|--------|
| `test_creates_source` | 提供完整合法参数 | 201，返回的 name 与请求一致 |
| `test_rejects_missing_name` | name 字段缺失 | 400 |
| `test_rejects_missing_base_url` | base_url 字段缺失 | 400 |
| `test_viewer_cannot_create` | viewer 角色尝试创建 | 403 |

#### `TestGetDataSource`

| 测试方法 | 场景 | 验证点 |
|----------|------|--------|
| `test_returns_source` | 请求存在的 ID | 200，name 为 "校园网通知公告" |
| `test_returns_404` | 请求不存在的 ID (99999) | 404 |

#### `TestUpdateDataSource`

| 测试方法 | 场景 | 验证点 |
|----------|------|--------|
| `test_updates_source` | 更新 name 字段 | 200，name 变为新值 |

#### `TestDataSourceLogs`

| 测试方法 | 场景 | 验证点 |
|----------|------|--------|
| `test_returns_logs` | 获取指定数据源的日志 | 200，`items` 存在 |

#### `TestDeleteDataSource`

| 测试方法 | 场景 | 验证点 |
|----------|------|--------|
| `test_deletes_source` | 删除存在的 ID | 200，`success` 为 true；再次 GET 返回 404 |
| `test_returns_404` | 删除不存在的 ID | 404 |
| `test_requires_admin` | viewer 角色尝试删除 | 403 |
| `test_requires_auth` | 未携带 JWT | 401 |

### 当前限制

- 缺少 `POST /api/data-sources/{id}/crawl` 端点的集成测试（`test_crawl`）
- 缺少创建时 `crawl_mode` / `source_level` 非法值的覆盖
- 缺少 PUT 的 400/403/404 分支测试

## 2. `test_data_source_service.py` -- 数据源服务单元测试

### 测试策略

在 Flask 应用上下文中直接调用服务层函数，验证数据库读写、字段校验和错误处理。使用 `app` fixture 的 app context 操作测试数据库。

### 依赖的 Fixture

- `app`：Flask 应用（提供 app context）
- `sample_data_source`：预先创建的数据源记录

### 测试类与场景

#### `TestValidateBaseUrl`

| 测试方法 | 场景 | 验证点 |
|----------|------|--------|
| `test_accepts_http` | `http://` 开头 | 返回原值 |
| `test_accepts_https` | `https://` 开头 | 返回原值 |
| `test_rejects_no_scheme` | 无协议前缀 | 抛出 `ValueError` |
| `test_rejects_ftp` | `ftp://` 开头 | 抛出 `ValueError` |

## 3. `test_security_service.py` -- 安全服务单元测试

### 测试策略

纯函数测试，不需要数据库或 Flask 上下文。直接调用 `security_service` 中的函数和校验方法，覆盖成功路径和安全拦截场景。

### 测试类与场景

#### `TestIsInternal`

| 测试方法 | 场景 | 验证点 |
|----------|------|--------|
| `test_localhost_is_internal` | "localhost" | True |
| `test_loopback_is_internal` | "127.0.0.1" | True |
| `test_private_10_range_is_internal` | "10.0.0.1" | True |
| `test_private_192_168_is_internal` | "192.168.1.1" | True |
| `test_public_domain_is_not_internal` | "example.edu.cn" | False |

#### `TestMatchesAnyDomain`

| 测试方法 | 场景 | 验证点 |
|----------|------|--------|
| `test_exact_match` | 精确匹配 | True |
| `test_subdomain_match` | 子域名匹配 | True |
| `test_wildcard_match` | `*.` 通配符匹配 | True |
| `test_wildcard_exact_match` | 通配符精确匹配 | True（"example.edu.cn" 匹配 "*.example.edu.cn"） |
| `test_no_match` | 无匹配 | False |
| `test_multiple_domains` | 多域名列表 | 命中正确域名 |
| `test_empty_allowed_list` | 空白名单 | False |

#### `TestValidateTargetUrl`

| 测试方法 | 场景 | 验证点 |
|----------|------|--------|
| `test_allows_valid_url_with_allowed_domain` | 合法 HTTPS + 允许域名 | 返回原 URL |
| `test_rejects_internal_ip` | 127.0.0.1 | 抛出 SecurityError |
| `test_rejects_localhost` | localhost | 抛出 SecurityError |
| `test_rejects_non_allowed_domain` | 域名不在白名单 | 抛出 SecurityError，消息含 "not in allowed domains" |
| `test_rejects_disallowed_scheme` | ftp 协议 | 抛出 SecurityError，消息含 "Disallowed URL scheme" |
| `test_allows_url_without_domain_list` | 不传 allowed_domains | 通过校验 |

#### `TestCheckRedirectSafety`

| 测试方法 | 场景 | 验证点 |
|----------|------|--------|
| `test_allows_same_origin_redirect` | 同域名重定向 | 返回重定向后的 URL |
| `test_rejects_cross_domain_redirect` | 跨域名重定向 | 抛出 SecurityError，消息含 "Cross-domain redirect" |
| `test_returns_original_for_no_redirect` | 无重定向 | 返回原 URL |

#### `TestSanitiseCrawledText`

| 测试方法 | 场景 | 验证点 |
|----------|------|--------|
| `test_escapes_html_tags` | HTML 标签 | `<script>` 被转义 |
| `test_strips_control_characters` | 控制字符 | `\x00`、`\x08` 被移除 |

#### `TestMaskSensitive`

| 测试方法 | 场景 | 验证点 |
|----------|------|--------|
| `test_masks_phone_numbers` | 手机号 | 原文被替换为掩码形式（前 3 + "****" + 后 2） |
| `test_masks_id_card` | 身份证号 | 原文被替换为掩码形式 |
