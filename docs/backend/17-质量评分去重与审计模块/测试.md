## quality_service 测试（`test_quality_service.py`）

### 测试策略

纯函数测试。`score_poster()` 接收 `Poster` 对象和两个布尔标志，返回 `(score, notes)`。测试通过构造不同属性组合的 Poster 对象来验证评分规则。

### Mock 策略

**无需 mock。** 直接使用 `Poster(**kwargs)` 构造测试对象，不需要数据库或外部服务。使用 `_make_poster()` 辅助函数提供默认完整的海报属性。

### 测试用例清单

| 测试类 | 测试方法 | 场景 |
|--------|----------|------|
| `TestScorePoster` | `test_full_poster_scores_100` | 完整海报评分 100，无 notes |
| | `test_official_source_bonus` | 官方来源加 10 分，但上限 100 |
| | `test_empty_title_penalty` | 标题为空扣 30 分 |
| | `test_short_title_penalty` | 标题过短（<5 字）扣 15 分 |
| | `test_missing_summary_penalty` | 摘要为空扣 15 分 |
| | `test_missing_event_time_penalty` | 缺少活动时间扣 15 分 |
| | `test_missing_location_penalty` | 缺少活动地点扣 10 分 |
| | `test_missing_source_url_penalty` | 缺少来源链接扣 10 分 |
| | `test_short_raw_text_penalty` | 正文过短（<50 字符）扣 10 分 |
| | `test_moderately_short_raw_text_penalty` | 正文偏短（<200 字符）扣 5 分 |
| | `test_duplicate_penalty` | 疑似重复扣 20 分 |
| | `test_score_clamped_to_range` | 分数限制在 [0, 100] 区间 |

### 关键场景说明

1. **扣分叠加**：多个缺项同时存在时扣分值累加
2. **分数截断**：`max(0, min(100, score))` 确保最终分数不超出边界
3. **加分不溢出**：官方来源 +10 但上限 100，所以满分海报加分后仍然是 100
4. **正文长度梯度**：50 字符以下扣 10 分，50-200 字符扣 5 分，200 以上不扣分

## dedup_service 测试（`test_dedup_service.py`）

### 测试策略

分层测试：先测试底层辅助函数（标题归一化、位置归一化、哈希生成），再测试组合指纹生成，最后测试数据库交互的 `check_duplicates()`。

### Mock 策略

- 纯函数（`_normalize_title`、`_normalize_location`、`generate_title_key`、`generate_source_key`、`generate_fingerprint`）直接调用，无需 mock
- `check_duplicates()` 需要 `app.app_context()` 和 SQLite 内存数据库来查询 `Poster` 表

### 测试用例清单

| 测试类 | 测试方法 | 场景 |
|--------|----------|------|
| `TestNormalizeTitle` | `test_removes_punctuation` | 去除标点符号，保留字母和汉字 |
| | `test_normalizes_whitespace` | 合并多余空格 |
| | `test_preserves_chinese_and_alphanumeric` | 保留中文和字母数字 |
| | `test_empty_string_returns_empty` | 空白字符串返回空 |
| `TestNormalizeLocation` | `test_normalizes_location` | 位置字符串归一化 |
| | `test_returns_none_for_empty` | 空/None 返回 None |
| `TestGenerateTitleKey` | `test_generates_consistent_hash` | 相同标题产生相同 MD5 |
| | `test_different_titles_produce_different_keys` | 不同标题产生不同 MD5 |
| | `test_empty_title_returns_empty` | 空标题返回空字符串 |
| `TestGenerateSourceKey` | `test_generates_md5_from_url` | URL 生成 32 位 MD5 |
| | `test_strips_trailing_slash` | 尾部斜杠不影响哈希 |
| | `test_returns_none_for_no_url` | 空/None URL 返回 None |
| `TestGenerateFingerprint` | `test_produces_consistent_fingerprint` | 相同输入产生相同指纹 |
| | `test_different_location_produces_different_fingerprint` | 不同位置产生不同指纹 |
| | `test_handles_none_location` | location 为 None 时仍生成指纹 |
| | `test_handles_none_date` | date 为 None 时仍生成指纹 |
| `TestCheckDuplicates` | `test_no_duplicates_for_new_poster` | 全新海报不标记为重复 |

### 关键场景说明

1. **哈希一致性**：同一字符串重复调用必须返回相同 MD5，这是去重的基础
2. **URL 归一化**：去除尾部斜杠确保 `https://example.com/url/` 与 `https://example.com/url` 归并
3. **指纹组成**：`fingerprint = MD5(title_key + "|" + date_key + "|" + location_key)`，各部分可缺
4. **数据库中优先级**：先匹配 `source_fingerprint`（精确 URL），再匹配 `source_fingerprint`（标题+日期+地点模糊）

## audit_service 测试（`test_audit_service.py`）

### 测试策略

测试 `create_audit_log()` 的数据库写入行为，验证所有字段正确存储。

### Mock 策略

使用 `app.app_context()` + SQLite 内存数据库。直接调用 `create_audit_log()`，然后通过 `AuditLog.query.get()` 验证持久化。

### 测试用例清单

| 测试类 | 测试方法 | 场景 |
|--------|----------|------|
| `TestCreateAuditLog` | `test_creates_log_with_all_fields` | 全字段审计日志创建和验证 |
| | `test_creates_log_with_minimal_fields` | 仅 `actor_id` + `action` 的最小记录 |
| | `test_log_is_persisted` | 日志可被重新查询到 |
| | `test_metadata_with_chinese_characters` | 中文元数据正确序列化 |

### 关键场景说明

1. **字段可空性**：`target_type`、`target_id`、`summary`、`metadata_json` 均允许为 None
2. **中文编码**：`metadata` 中的中文字符通过 `json.dumps(ensure_ascii=False)` 正确存储
3. **不提交**：`create_audit_log()` 仅 `flush()`，调用方负责 `commit()`

## audit_logs API 测试（`test_audit_logs_api.py`）

### 测试策略

集成测试，验证审计日志 API 的查询、过滤和权限控制。

### Mock 策略

使用 Flask 测试配置 + SQLite 内存数据库。`client` fixture 提供 HTTP 客户端，通过 `sample_poster` fixture 创建测试数据。

### 测试用例清单

| 测试类 | 测试方法 | 场景 |
|--------|----------|------|
| `TestListAuditLogs` | `test_returns_logs` | 返回审计日志列表（可能为空） |
| | `test_logs_appear_after_poster_action` | 执行海报操作后日志可见 |
| | `test_requires_auth` | 无 JWT 返回 401 |

### 关键场景说明

1. **触发记录**：提交审核等操作会触发 `create_audit_log()`，API 查询应能看到这些记录
2. **Admin 权限**：返回 403 的测试依赖于 `roles_required("admin")` 装饰器

## export API 测试（`test_export_api.py`）

### 测试策略

集成测试，验证三个导出端点的数据输出和权限控制。

### Mock 策略

### 测试用例清单

| 测试类 | 测试方法 | 场景 |
|--------|----------|------|

## 测试覆盖率总结

| 模块 | 行覆盖率（估计） | 关键断言 |
|------|-----------------|----------|
| `quality_service.py` | ~95% | 每项扣分规则独立覆盖；边界截断覆盖；加分不溢出 |
| `dedup_service.py` | ~90% | 全部辅助函数覆盖；空/边界输入覆盖；一致性验证 |
| `audit_service.py` | ~85% | 字段存储覆盖；中文编码；minimal/maximal 模式 |
| audit_logs API | ~70% | 列表查询；操作触发记录；权限控制 |
| export API | ~80% | 三种导出格式覆盖；权限控制 |

### 未覆盖但建议补充测试的路径

1. **dedup_service.py 的 `check_duplicates()`**：当前只有"无重复"的测试，缺少发现重复的场景（需在数据库预先插入重复数据）
2. **export API 的 demo/summary**：缺少统计计数的精确性验证
3. **quality_service.py**：`organizer` 字段虽然存在于 Poster 模型但未被评分函数使用——可以考虑是否需要增加该字段的校验
