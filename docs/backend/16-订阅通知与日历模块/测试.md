## 订阅 API 集成测试（`test_subscriptions_api.py`，建议）

### 测试策略

通过 Flask 测试客户端发送 HTTP 请求，验证订阅的创建、列表查询和删除。需覆盖权限校验和参数校验。

### Mock 策略

使用 Flask 测试配置 + SQLite 内存数据库。`client` fixture 提供测试客户端，`admin_headers` / `viewer_headers` 提供 JWT 认证头。

### 建议的测试用例

| 测试类 | 测试方法 | 场景 |
|--------|----------|------|
| `TestCreateSubscription` | `test_creates_by_node_id` | 按知识节点创建订阅，返回 201 |
| | `test_creates_by_keyword` | 按关键词创建订阅，返回 201 |
| | `test_rejects_empty_body` | 既无 node_id 也无 keyword，返回 400 |
| | `test_rejects_both_params` | 同时提供 node_id 和 keyword，返回 400 |
| | `test_idempotent_on_duplicate` | 重复创建相同订阅，返回 200 而非 201 |
| | `test_requires_auth` | 无 JWT 返回 401 |
| `TestListSubscriptions` | `test_returns_user_subscriptions` | 返回当前用户的所有订阅 |
| | `test_returns_empty_list` | 无订阅时返回空数组 |
| | `test_other_users_not_included` | 不返回其他用户的订阅 |
| `TestDeleteSubscription` | `test_deletes_own_subscription` | 删除自己的订阅，返回 200 |
| | `test_cannot_delete_others` | 尝试删除他人的订阅，返回 403 |
| | `test_returns_404_for_missing` | 不存在的 ID 返回 404 |

### 关键场景说明

1. **幂等创建**：同用户同 `node_id`/`keyword` 的重复订阅不报错，直接返回现有记录
2. **权限隔离**：订阅列表和删除操作均限制为当前认证用户的数据
3. **约束检查**：`node_id` 和 `keyword` 不能同时为空，也不能同时非空

## 日历 API 集成测试（`test_calendar_api.py`，建议）

### 测试策略

测试日历事件 CRUD 和 ICS 下载。ICS 下载接口公开，无需认证；日历事件管理需认证。

### 建议的测试用例

| 测试类 | 测试方法 | 场景 |
|--------|----------|------|
| `TestDownloadICS` | `test_downloads_ics_for_published` | 已发布海报返回 ICS 文件内容 |
| | `test_rejects_unpublished` | 未发布海报返回 404 |
| | `test_ics_contains_correct_fields` | ICS 内容包含 UID/DTSTART/SUMMARY 等必要字段 |
| | `test_no_auth_required` | 无需 JWT 即可访问 |
| `TestAddCalendarEvent` | `test_adds_event` | 添加日历事件返回 201 |
| | `test_idempotent_on_duplicate` | 重复添加返回 200 |
| | `test_rejects_missing_poster_id` | 缺少 poster_id 返回 400 |
| | `test_rejects_unpublished_poster` | 未发布海报返回 404 |
| `TestListCalendarEvents` | `test_returns_events_ordered_by_time` | 按活动时间升序排列 |
| | `test_returns_empty_for_new_user` | 无事件时返回空数组 |
| `TestRemoveCalendarEvent` | `test_removes_event` | 移除事件返回 200 |
| | `test_returns_404_if_not_in_calendar` | 未添加的事件返回 404 |

### 关键场景说明

1. **ICS 文件格式**：需验证 RFC 5545 合规——`BEGIN:VCALENDAR` / `VERSION:2.0` / `BEGIN:VEVENT` / `END:VCALENDAR` 等
2. **海报状态校验**：仅 `published` 状态的海报可下载 ICS 和添加日历
3. **时间排序**：日历列表按 `Poster.event_time` 升序，无时间的事件排在最后

## Notification Service 单元测试（`test_notification_service.py`，建议）

### 测试策略

`notification_service.dispatch_notifications()` 是纯逻辑函数，通过构造模拟的 Poster 和 Subscription 对象测试匹配逻辑。

### Mock 策略

- 使用 `app.app_context()` 和 SQLite 内存数据库
- 在数据库创建测试用的 `KnowledgeNode`、`Subscription`、`Poster`、`PosterNode` 记录
- 不需要 mock 外部服务

### 建议的测试用例

| 测试类 | 测试方法 | 场景 |
|--------|----------|------|
| `TestDispatchNotifications` | `test_dispatches_for_node_match` | 订阅的知识节点匹配到海报，创建通知 |
| | `test_dispatches_for_keyword_match` | 订阅的关键词匹配到海报字段，创建通知 |
| | `test_skips_non_published` | 非 published 状态的海报不触发通知 |
| | `test_deduplicates_by_user` | 同一用户匹配多个订阅仅产生一条通知 |
| | `test_no_match_no_notification` | 无匹配订阅时不创建通知 |
| | `test_keyword_matches_title` | 关键词匹配海报标题 |
| | `test_keyword_matches_tags` | 关键词匹配海报标签 |
| | `test_case_insensitive_keyword` | 关键词匹配不区分大小写 |

### 关键场景说明

1. **去重逻辑**：同一用户通过 node 和 keyword 同时匹配时，只产生一条通知（node 优先）
2. **状态守卫**：`dispatch_notifications()` 内部检查 `poster.status == "published"`，非 published 海报直接返回空列表
3. **搜索文本构成**：关键词匹配作用于拼接的 `title + activity_type + tags + location + organizer` 字符串

## Calendar Service 单元测试（`test_calendar_service.py`，建议）

### 测试策略

`calendar_service.generate_ics()` 是纯函数——输入 `Poster` 对象，输出 ICS 字符串。不使用数据库或外部依赖。

### Mock 策略

直接构造 `Poster` 对象（填充必要属性），无需 mock。

### 建议的测试用例

| 测试类 | 测试方法 | 场景 |
|--------|----------|------|
| `TestGenerateICS` | `test_contains_vcalendar_envelope` | ICS 包含 VCALENDAR 头尾 |
| | `test_contains_vevent` | ICS 包含 VEVENT 块 |
| | `test_uid_format` | UID 格式为 `poster-{id}@campus-activity-platform` |
| | `test_summary_is_title` | SUMMARY 为海报标题 |
| | `test_includes_location` | 包含 LOCATION 字段 |
| | `test_includes_description` | 包含 DESCRIPTION（当有 summary 时） |
| | `test_escapes_special_chars` | 特殊字符（分号、逗号、反斜杠、换行）正确转义 |
| | `test_fallback_to_created_at` | 无 event_time 时使用 created_at |
| | `test_default_2h_duration` | 默认持续 2 小时 |
| | `test_rfc_5545_compliance` | 行尾为 CRLF |

### 关键场景说明

1. **RFC 5545 转义**：`;`、`,`、`\`、`\n` 需要被正确转义
2. **时间回退**：当海报无 `event_time` 时，使用 `created_at` 作为起始时间
