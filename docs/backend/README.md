| 功能模块 | 10-17 | 独立文件夹 + 三文件结构（见下） | 每个模块独立文件夹，按职责拆分为三个文件 |

### 功能模块三文件规范

每个功能模块文件夹（10-17）**必须**包含以下三个文件，内容严格独立、不可重叠：

```
XX-模块名/
├── 模块设计.md    ← 设计文档：功能职责、设计思路、业务逻辑、实现策略
├── API接口.md     ← 接口文档：每个端点的 method/path、权限、请求体/参数、成功响应 JSON、错误码
└── 测试.md        ← 测试文档：测试文件位置、覆盖场景、Mock 策略、覆盖率分析
```

**内容边界：**

| 文件 | 写什么 | 不写什么 |
|------|--------|---------|
| 模块设计.md | 为什么这样设计、处理流程、安全约束、降级策略 | 不写 API 请求/响应格式（那是 API 接口的事） |
| API接口.md | 每个端点完整的请求格式和返回结构、权限要求、错误码 | 不写设计理由、不写处理流程（那是模块设计的事） |
| 测试.md | 测试文件有哪些、每个文件测什么、Mock 了什么、覆盖率缺口 | 不写接口定义、不写业务逻辑说明（那是 API 接口和模块设计的事） |

**API接口.md 端点文档格式：**

每个端点必须包含：
- 功能一句话说明
- 权限要求
- 请求参数（路径参数 / 查询参数 / 请求体，含字段类型和必填/可选）
- 成功响应（带完整 JSON 示例）
- 错误码列表（含状态码和错误信息）

**测试.md 必须包含：**
- 对应的测试文件路径和文件名
- 测试用例分类（API 集成测试 vs 单元测试 vs Mock 测试）
- Mock 策略说明（Mock 了什么外部依赖，为什么）
- 关键测试场景表
- 已知覆盖率缺口

## 首页接口

### `GET /api/home/featured`

获取首页推荐活动列表（公开，无需认证）。返回最近发布的 3 条已上线海报。

**响应示例：**
```json
{
  "items": [
    {
      "id": 1,
      "title": "活动标题",
      "summary": "活动简介",
      "event_time": "2026-06-01T19:00:00",
      "location": "活动地点",
      "organizer": "主办方",
      "activity_type": "讲座",
      "created_at": "2026-05-23T10:00:00"
    }
  ]
}
```
