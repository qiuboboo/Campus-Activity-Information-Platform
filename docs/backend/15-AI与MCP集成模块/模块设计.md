# AI 与 MCP 集成模块设计

## 设计原则

采用"AI 增强，而不是 AI 依赖"的设计原则。AI 用于提高抽取效果、搜索广度和数据采集能力，但系统的基础功能不依赖 AI 服务是否可用。所有 AI 功能都有对应的非 AI 兜底实现。

## 模块划分

### Model Manager（`model_manager.py`）

- 多 LLM 模型配置发现与分发
- 通过 `list_llm_profiles()` 读取环境变量中所有命名模型配置
- 支持按 profile 名称切换模型（如 `default`、`copilot`、`deepseek`）

### AI Service（`ai_service.py`）

- 封装对 LLM API 的调用
- 提供活动信息提取、摘要生成、分类标签等能力
- 支持多种 LLM 后端（DeepSeek / OpenAI / Claude / Copilot Pro 等）
- 所有调用记录来源、参数摘要、执行时长和结果状态

### Fallback Extractor（`fallback_extractor.py`）

- 基于正则表达式的非 AI 兜底提取模块
- 在 LLM 不可用时自动降级，提取标题、时间、地点、主办方、摘要
- 支持中文日期格式（"2025年5月10日晚7点"→ `19:00`）
- 返回结构与 LLM 版本一致，附带 `_fallback: true` 标记

### MCP Client（`mcp_service.py`）

- 封装 MCP（Model Context Protocol）客户端
- 连接外部 MCP 服务器，如小红书 MCP、搜索引擎 MCP 等
- 为爬虫和数据采集提供统一的外部数据入口
- 通过配置文件管理可用的 MCP 服务器列表和认证信息

### Dict Manager（`dict_manager.py`）

- 受控词表管理，提供地点、组织、主题的别名标准化
- 内置常见别名映射（如"大活礼堂"→"大学生活动中心大礼堂"）
- 知识节点生成时自动标准化 location 和 organizer
- 提供 REST API 管理词条

### Embedding Service（`embeddings_service.py`）

- 将文本转为向量嵌入，通过 OpenAI 兼容 API 调用
- 提供 `get_embedding()` — 单文本向量化，含内存缓存
- 提供 `cosine_similarity()` — 向量余弦相似度计算
- 提供 `search_posters_by_vector()` — 按向量相似度对海报列表排序
- 配合 Celery `index` 队列任务异步生成和存储 Embedding

## 适用场景

- 活动文本语义抽取（AI Service）
- 外部站点搜索（AI Service + 爬虫）
- 社交平台数据采集（MCP Client）
- 智能摘要与分类标签生成（AI Service）
- 检索增强与结果重排（AI Service）

## 集成方式

- Flask 后端直接调用 `ai_service.py` 和 `mcp_service.py` 中的函数
- 服务层封装统一的调用接口
- 通过环境变量配置 LLM API Key、模型选择和 MCP 服务器地址
- 耗时 AI 调用可通过 Celery 异步执行

## 数据流

```
现有爬虫抓到文本
    ↓
ai_service.extract_from_text(text)  ← 调用 LLM 提取结构化字段
    ↓
存入 Poster（现有流程）
    ↓
ai_service.enrich_poster(poster_id)  ← LLM 生成摘要、分类
    ↓
写入知识图谱（现有规则流程）

---

外部数据采集（如小红书）
    ↓
mcp_service.search(query)  ← 通过 MCP 协议搜索
    ↓
ai_service 处理结果 → 创建数据源条目 → 进入审核流程
```

## 安全与运行约束

- LLM API Key 和 MCP 认证信息统一使用环境变量管理
- 外部 MCP 服务列表由管理员配置，不允许用户动态添加
- AI 调用设置超时和重试上限
- 所有 AI 和 MCP 调用记录日志
- 当 LLM 或 MCP 服务不可用时，系统自动降级到非 AI 兜底方案

## 接入优先级

1. **第一优先级**：学校官网、学院官网、专题活动页（基础爬虫 + 规则提取，无需 AI）
2. **第二优先级**：社交媒体平台（MCP 客户端 + LLM 内容提取和筛选）
3. **第三优先级**：外部搜索引擎补充（SearXNG 多引擎搜索 + 搜狗微信搜索）
4. **第四优先级**：企业微信、飞书等协作平台

## AI 与非 AI 兜底对照

| 功能 | AI 实现 | 非 AI 实现 |
|------|---------|-----------|
| 海报信息抽取 | LLM 识别标题、时间、地点等 | 正则表达式 + 表单字段 + 关键词规则 |
| 知识节点生成 | 识别隐含主题、系列活动归属 | 预定义类型 + 字典标准化 + 规则匹配 |
| 海报关系生成 | 语义判断潜在联系 | same_day/same_place/same_org/same_topic 规则建边 |
| 内部搜索 | 向量语义检索 | PostgreSQL 全文检索 + 标签过滤 |
| 外部搜索 | LLM 驱动搜索 + MCP 服务 | SearXNG 多引擎搜索 + 搜狗微信搜索 |
| 网页内容解析 | 复杂页面理解、摘要提取 | requests + BeautifulSoup + CSS Selector |

## 兜底设计的意义

- LLM/MCP 异常时系统仍可完成基础活动发布和查询
- 规则和字典方案更易解释、调试和维护
- 体现系统工程思维，不是单纯依赖模型能力
- 更换 AI 提供商或关闭部分 MCP 服务后主流程仍可运行

AI 作为"增强层"，基础规则、字典、数据库和爬虫构成"稳定底座"。
