# AI 与 MCP 集成模块测试

## 测试文件结构

本模块的测试分布在以下文件中：

| 文件 | 类型 | 覆盖范围 |
|------|------|----------|
| `backend/tests/test_fallback_extractor.py` | 单元测试 | `fallback_extractor.fallback_extract()` — 兜底提取器的每个字段提取函数 |
| `backend/tests/test_dicts_api.py` | 集成测试 | 受控词表 API 全部端点（CRUD + seed） |

---

## fallback_extractor 测试（`test_fallback_extractor.py`）

### 测试策略

兜底提取器是纯函数，无外部依赖——输入文本字符串，输出结构化字典。测试采用纯单元测试方式，针对每个提取函数构造典型输入，验证输出字段的准确性。

### Mock 策略

**无需 mock。** `fallback_extract()` 不涉及任何数据库、网络或外部 API 调用，完全基于正则表达式和字符串处理。

### 测试用例清单

| 测试类 | 测试方法 | 场景 |
|--------|----------|------|
| `TestFallbackExtract` | `test_extracts_title_from_first_line` | 标题取自首行非空文本 |
| | `test_extracts_event_time_chinese_format` | 中文日期格式（"2026年5月10日19:00"）解析 |
| | `test_extracts_event_time_iso_format` | ISO 日期格式（"2026-05-10"）解析 |
| | `test_extracts_location` | 从"在...举行"模式中提取地点 |
| | `test_extracts_organizer` | 从"由...主办"模式中提取主办方 |
| | `test_extracts_tags` | 根据关键词匹配标签（"科技"、"讲座"） |
| | `test_extracts_activity_type` | 从标签映射到活动类型 |
| | `test_empty_input_returns_empty` | 空字符串输入返回空字典 |
| | `test_none_input_returns_empty` | None 输入返回空字典 |
| | `test_extracts_evening_time_with_12h_conversion` | 12小时制转换（"晚7点30分" -> 19:30） |
| | `test_location_with_venue_suffix` | 场地后缀匹配（"报告厅"、"礼堂"等） |
| | `test_organizer_with_org_suffix` | 组织后缀匹配（"学生会"、"学院"等） |

### 关键场景说明

1. **中文日期解析**：支持三种格式——中文数字日期（"2026年5月10日"）、月日格式（"5月10日"）、ISO 格式（"2026-05-10"）
2. **12小时制转换**："晚7点"、"晚上7点"、"下午2点"等自动转换为 24 小时制
3. **时间后缀匹配**：时间跟在日期后 40 字符内才被识别为活动时间
4. **地点和组织提取优先级**：按模式列表顺序匹配，返回第一个成功的匹配

## dicts API 测试（`test_dicts_api.py`）

### 测试策略

受控词表 API 的集成测试，通过 Flask 测试客户端发送真实 HTTP 请求，验证端点行为、权限控制、参数校验和数据库交互。

### Mock 策略

使用 Flask 应用的测试配置（`app` fixture）和 SQLite 内存数据库。不需要 mock 外部服务，因为 dict 操作完全在数据库层面完成。

**Fixtures 依赖：**
- `client` — Flask 测试客户端
- `admin_headers` — 包含 admin 角色 JWT 的请求头
- `viewer_headers` — 包含 viewer 角色 JWT 的请求头
- `app` — Flask 应用实例（用于直接数据库操作）

### 测试用例清单

| 测试类 | 测试方法 | 场景 |
|--------|----------|------|
| `TestListDicts` | `test_returns_entries` | 列出词条返回正确结构 |
| | `test_filter_by_query` | 按关键词搜索过滤 |
| | `test_pagination` | 分页参数生效 |
| | `test_requires_auth` | 无 JWT 返回 401 |
| `TestCreateDict` | `test_creates_entry` | 创建词条成功返回 201 |
| | `test_rejects_missing_standard_name` | 缺少 `standard_name` 返回 400 |
| | `test_viewer_cannot_create` | viewer 角色返回 403 |
| `TestUpdateDict` | `test_updates_entry` | 更新词条成功返回 200 |
| | `test_returns_404_for_missing` | 不存在的 ID 返回 404 |
| `TestDeleteDict` | `test_deletes_entry` | 删除词条返回 `{"deleted": true}` |
| | `test_returns_404_for_missing` | 不存在的 ID 返回 404 |
| `TestSeedDict` | `test_seeds_builtin_entries` | 初始化内置别名映射 |

### 关键场景说明

1. **权限分层验证**：每类操作分别测试 admin（允许）和 viewer（拒绝）两种角色
2. **参数校验**：缺少必填字段（`standard_name`）返回 400，错误的 category 值（如 `/dict/invalid`）由服务层校验
3. **幂等性**：seed 操作可重复调用，不会重复创建已存在的条目

## 测试覆盖率总结

| 模块 | 行覆盖率（估计） | 关键断言 |
|------|-----------------|----------|
| `fallback_extractor.py` | ~90% | 每个字段提取函数独立覆盖；边界情况（空输入、None、特殊日期格式）覆盖 |
| `dict_manager.py` | 通过 API 集成测试间接覆盖 | CRUD 操作 + 权限 + 参数校验全覆盖 |

### 未覆盖但建议补充测试的路径

1. **ai_service.py**：`_llm_chat()` 中的重试逻辑、profile 解析失败降级、LLM 不可用时的 fallback 路径
2. **mcp_service.py**：server 进程启停、JSON-RPC 通信、server 未配置/启动失败路径
3. **dict_manager.py**：`normalize()` 和 `normalize_all()` 的别名匹配逻辑（当前仅通过 API 间接测试）
4. **embeddings_service.py**：API 调用失败、缓存命中/未命中、余弦相似度计算
