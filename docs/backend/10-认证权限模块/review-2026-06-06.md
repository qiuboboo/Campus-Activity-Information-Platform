## 发现的问题

### 1. `create_captcha()` 在测试环境崩溃 (已修复)

**文件**: `app/services/captcha_service.py:84`

**问题**: `create_captcha()` 直接调用 `_get_redis().setex(...)`，但 `_get_redis()` 在 Redis 未配置时返回 None。`validate_captcha` 和 `send_verification_code` 都有 TESTING 模式跳过，唯独 `create_captcha` 没有。

**修复**: 在 `create_captcha()` 开头增加 TESTING 模式判断，返回 1×1 像素占位图 + 固定 token，与 `validate_captcha` 的 TESTING 跳过逻辑对齐。

### 2. 模块设计文档过薄

**文件**: `docs/backend/10-认证权限模块/模块设计.md`

文档只有角色定义和历史改进记录，缺少：
- 验证码生成策略（数字位数、图片尺寸、噪音线/噪点、Redis TTL）
- Redis key 命名规范 (`captcha:{token}`, `verify:code:{email}`, `verify:cooldown:{email}`)
- 密码哈希方案（werkzeug SHA256）
- JWT claims 结构 (`identity`, `role`, `username`)
- 邮箱验证码冷却期设计（60秒）
- 测试模式下的降级行为

### 3. 测试文档未更新

**文件**: `docs/backend/10-认证权限模块/测试.md`

测试文档只记录了 login 和 me 两个测试类，新增的 Register/Captcha/SendCode 测试类未列入。且文档中未说明 captcha 和 send-code 端点的 mock 策略。
