# 认证接口测试

## 测试文件

| 文件 | 类型 | 路径 |
|------|------|------|
| 认证 API 集成测试 | 集成测试（API） | `backend/tests/test_auth_api.py` |

## 运行测试

```bash
# 运行所有认证相关测试
cd backend && python -m pytest tests/test_auth_api.py -v

# 运行单个测试类
cd backend && python -m pytest tests/test_auth_api.py::TestLogin -v

# 运行单个测试用例
cd backend && python -m pytest tests/test_auth_api.py::TestLogin::test_login_with_valid_credentials -v
```

## 测试覆盖范围

### `TestLogin` — 登录接口测试

| 测试方法 | 场景 | 验证点 |
|----------|------|--------|
| `test_login_with_valid_credentials` | 使用有效的 admin 账号密码登录 | 返回 200，响应中包含 `token` 和 `user`，用户名匹配 |
| `test_login_with_invalid_password` | 使用错误密码登录 | 返回 401 |
| `test_login_missing_username` | 请求体缺少用户名 | 返回 400 |
| `test_login_missing_password` | 请求体缺少密码 | 返回 400 |

### `TestMe` — 当前用户信息接口测试

| 测试方法 | 场景 | 验证点 |
|----------|------|--------|
| `test_returns_user_info` | 携带有效 JWT 获取用户信息 | 返回 200，用户名和角色正确 |
| `test_returns_401_without_token` | 不携带 JWT 访问 | 返回 401 |

## 测试配置与固件

### 测试配置（`TestConfig`）

定义在 `backend/tests/conftest.py` 中，基于 `Config` 覆写：

- `TESTING = True`：启用 Flask 测试模式
- `SQLALCHEMY_DATABASE_URI = "sqlite:///:memory:"`：使用内存数据库
- `JWT_SECRET_KEY = "test-secret"`：固定 JWT 密钥
- `REDIS_URL = ""`：禁用 Redis（验证码等 Redis 依赖被跳过）
- `EMBEDDING_ENABLED = False`：禁用向量嵌入

### 关键固件（Fixtures）

| 固件 | 说明 |
|------|------|
| `app` | 创建测试 Flask 应用 + 推入应用上下文 + 创建所有表 + 预置 admin 用户 |
| `client` | Flask 测试客户端 |
| `admin_user` | 查询预置的 admin 用户 |
| `admin_token` | 为 admin 用户生成 JWT |
| `admin_headers` | `{"Authorization": "Bearer <admin_token>"}` |
| `publisher_user` | 创建 publisher 角色用户 |
| `publisher_headers` | publisher 用户的认证头 |
| `viewer_user` | 创建 viewer 角色用户 |
| `viewer_headers` | viewer 用户的认证头 |

### 认证模拟

- JWT 通过 `create_access_token(identity=str(user.id), additional_claims={"role": ..., "username": ...})` 直接生成
- 测试中无需经过登录接口获取 token
- `@jwt_required()` 装饰器通过测试客户端携带 `Authorization: Bearer <token>` 请求头触发验证

### 验证码测试行为

在 `TESTING` 模式下：
- 注册接口跳过邮箱验证码校验（`if current_app.config.get("TESTING", False): pass`）
- 图形验证码校验在测试中被测试用例自身覆盖（登录 API 直接提交用户名密码，验证码字段被留空）

## 关键测试场景说明

### 测试数据准备

`app` 固件在每次测试前执行以下操作：
1. 创建所有数据库表（`db.create_all()`）
2. 插入一个 admin 用户（username="admin", role="admin", password="admin123456"）
3. 测试结束后回滚（`db.drop_all()`）

每个测试方法运行在独立的数据库环境中，互不干扰。

### 无认证访问

测试使用 `client.get("/api/auth/me")`（不带认证头）验证 `@jwt_required()` 是否正确拒绝未认证请求，预期返回 401。

### 密码验证

`test_login_with_invalid_password` 验证 `check_password()` 方法的正确性——错误密码应当返回 401 而非 200。
