# 海报管理模块测试

## 测试文件

| 文件 | 类型 | 路径 |
|------|------|------|
| 海报 API 集成测试 | 集成测试（API） | `backend/tests/test_posters_api.py` |
| 海报服务单元测试 | 单元测试（Service） | `backend/tests/test_poster_service.py` |

## 运行测试

```bash
# 运行所有海报相关测试
cd backend && python -m pytest tests/test_posters_api.py tests/test_poster_service.py -v

# 运行单个测试文件
cd backend && python -m pytest tests/test_posters_api.py -v

# 运行单个测试类
cd backend && python -m pytest tests/test_poster_service.py::TestGeneratePosterHtml -v
```

## 测试配置与固件

### 应用配置

见 `conftest.py` 中 `TestConfig`，使用 SQLite 内存数据库，禁用 Redis 和 Embedding。

### 共享固件

| 固件 | 定义位置 | 说明 |
|------|----------|------|
| `app` | conftest.py | 创建应用、推上下文、建表、预置 admin 用户 |
| `client` | conftest.py | Flask 测试客户端 |
| `admin_headers` | conftest.py | `Authorization: Bearer <admin-jwt>` |
| `publisher_headers` | conftest.py | publisher 角色认证头 |
| `viewer_headers` | conftest.py | viewer 角色认证头 |
| `sample_poster` | conftest.py | 预创建的 draft 状态海报（标题："2026 校园科技文化节开幕式"） |
| `sample_published_poster` | conftest.py | 预创建的 published 状态海报，含知识节点（标题："AI 创新应用讲座"） |

### 角色权限模拟

- `@roles_required("publisher", "admin")`：使用 `viewer_headers` 请求返回 403
- `@roles_required("admin")`：使用 `publisher_headers` 请求返回 403
- `@jwt_required()`：不传 `Authorization` 头返回 401

### 数据隔离

每个测试用例运行在独立的数据库中（`app` 固件的 `db.create_all()` / `db.drop_all()` 生命周期）。`sample_poster` 和 `sample_published_poster` 固件在每个使用它们的测试中重新创建。

## 关键测试场景说明

### 海报状态机

测试覆盖了完整的草稿→审核→发布/驳回流程：
1. 创建海报得到 `draft` 状态
2. 提交审核变为 `pending_review`
3. 审核通过变为 `published`
4. 审核驳回变为 `rejected`
5. 非 `draft` 状态重复提交审核被拒绝（400）

### 角色权限验证

- **create / update / submit**：仅 `publisher` 和 `admin` 可操作，`viewer` 返回 403
- **review / queue / merge / rebuild / ai-enrich / duplicates**：仅 `admin` 可操作，`publisher` 返回 403
- **list / get**：所有已认证用户可操作

### 自动字段提取

`build_poster_fields()` 单元测试覆盖了：
- 从 `raw_text` 第一行自动提取标题
- 标题截断到 80 字符
- 摘要截断到 120 字符
- 带 fallback 时的合并策略（payload 覆盖 fallback）

### HTML 转义

`generate_poster_html()` 单元测试使用 `escape()` 防止 XSS 注入，验证 `<script>` 标签被转义为 HTML 实体。

### 合并操作

`TestMergeSource.test_merges_duplicate_source` 使用 `app.app_context()` 手动创建两个海报对象，验证合并后来源海报被删除、目标海报返回正确。
