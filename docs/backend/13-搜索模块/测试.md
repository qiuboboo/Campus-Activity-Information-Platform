# 搜索模块测试

## 测试文件结构

| 文件 | 类型 | 测试目标 |
|------|------|----------|
| `backend/tests/test_search_api.py` | 集成测试 | `POST /api/search/internal` 和 `POST /api/search/external` 端点 |
| `backend/tests/test_multi_search_service.py` | 单元测试 | `multi_search_service.search()` 及其内部辅助函数 |
| `backend/tests/test_external_search_llm_fallback.py` | 单元测试 | `ai_service.search_external()` 中的 LLM 兜底逻辑 |

## 1. `test_search_api.py` -- 搜索 API 集成测试

### 测试策略

使用 Flask 测试客户端发送真实 HTTP 请求，验证路由、认证、参数解析、响应结构。通过 conftest 中的 fixture 注入模拟数据。

### 依赖的 Fixture

- `client`：Flask 测试客户端
- `admin_headers`：带有管理员 JWT 的请求头
- `sample_published_poster`：数据库中预先创建的海报记录

### 测试类与场景

#### `TestInternalSearch`

| 测试方法 | 场景 | 验证点 |
|----------|------|--------|
| `test_searches_posters` | 搜索关键词匹配已有海报 | 返回 200，`items` 和 `query` 存在，query 值正确 |
| `test_searches_with_no_results` | 搜索词无匹配结果 | `items` 为空数组 |
| `test_empty_query_returns_empty` | q 参数为空 | 返回 200，非崩溃 |
| `test_requires_auth` | 未携带 JWT | 返回 401 |
| `test_search_mode_is_fulltext` | 默认检索模式 | `search_mode` 为 `"fulltext"` |
| `test_default_sort_is_relevance` | 不传 sort/order | `sort` 为 `"relevance"`、`order` 为 `"desc"` |
| `test_sort_by_title` | 指定 `sort=title&order=asc` | `sort` 和 `order` 反映请求值 |
| `test_sort_by_event_time` | 指定 `sort=event_time` | `sort` 为 `"event_time"` |
| `test_invalid_sort_falls_back_to_relevance` | 传入非法 sort/order 值 | 降级为 `sort=relevance`、`order=desc` |

#### `TestExternalSearch`

| 测试方法 | 场景 | 验证点 |
|----------|------|--------|
| `test_requires_query` | q 参数为空 | 返回 400 |
| `test_requires_auth` | 未携带 JWT | 返回 401 |
| `test_contract_fields_present` | 正常请求 | 响应包含 `error`、`query`、`results`、`count`、`source`，`source` 固定为 `"multi"`，`query` 与请求一致 |
| `test_error_when_all_engines_unreachable` | SearXNG 不可达 | 仍返回有效契约结构（`error`、`results`、`count`、`source` 字段存在） |
| `test_sources_param_is_accepted` | 传入 `sources=web` | 不崩溃，`source` 仍为 `"multi"` |

### 当前限制

- 测试环境无 SearXNG 实例，外部搜索的集成测试无法验证真实搜索结果内容
- 语义向量检索（`EMBEDDING_ENABLED=true`）路径缺少测试覆盖

## 2. `test_multi_search_service.py` -- 多引擎搜索服务单元测试

### 测试策略

通过 `unittest.mock.patch` 模拟 `requests.get`（SearXNG 调用）和 `weixin_search_service.sogou_search`（搜狗调用），隔离网络依赖。每个测试构造模拟的 HTTP 响应或搜狗返回值，验证搜索结果的合并、去重、错误处理逻辑。

### Mock 策略

| 依赖 | Mock 目标 | 方法 |
|------|-----------|------|
| SearXNG API | `app.services.multi_search_service.requests.get` | 设置 `return_value.status_code` 和 `return_value.json.return_value` |
| 搜狗微信搜索 | `app.services.weixin_search_service.sogou_search` | 直接设置 `return_value` 为模拟结果列表 |

### 测试类与场景

#### `TestSearch`

| 测试方法 | Mock 设定 | 验证点 |
|----------|-----------|--------|
| `test_returns_results_from_searxng` | SearXNG 返回 2 条结果（baidu + google），sogou 不在 engines 中 | 返回 2 条，source 正确，sogou 未被调用 |
| `test_includes_sogou_results` | SearXNG 返回 1 条，sogou 返回 1 条 | 合并后共 2 条，两条来源都有 |
| `test_deduplicates_by_url` | SearXNG 返回 2 条同 URL 结果 | 去重后保留 1 条，取首次出现 |
| `test_empty_query_returns_empty` | 查询词为空白 | 立即返回空结果，不发起任何网络请求 |
| `test_searxng_unavailable` | SearXNG 返回 503 | 返回空结果，`error` 非空 |
| `test_passes_engines_to_searxng` | 指定 engines 为 `["baidu", "duckduckgo"]` | 请求参数中 `engines` 为 `"baidu,duckduckgo"` |

#### `TestNormaliseResult`

| 测试方法 | 场景 | 验证点 |
|----------|------|--------|
| `test_standard_fields` | 完整原始结果 | title/summary 被 strip，source/url 正确映射 |
| `test_missing_url_becomes_none` | 结果无 url 字段 | url 映射为 None |

#### `TestDeduplicate`

| 测试方法 | 场景 | 验证点 |
|----------|------|--------|
| `test_removes_duplicates` | 多条相同 URL | 保留 2 条（1 条重复被移除） |
| `test_handles_empty_urls` | url 为 None 或 "" | 均保留，不做去重比较 |

## 3. `test_external_search_llm_fallback.py` -- LLM 兜底逻辑测试

### 测试策略

同时 mock `multi_search_service.search` 和 `ai_service._llm_chat`，控制多搜索引擎返回空结果，然后验证 LLM 兜底是否按预期触发或跳过。

### Mock 策略

| 依赖 | Mock 目标 | 典型设定 |
|------|-----------|----------|
| 多引擎搜索 | `app.services.multi_search_service.search` | `return_value = {"results": [], "error": None}` |
| LLM 调用 | `app.services.ai_service._llm_chat` | `return_value = [...]` 或 `None` |
| LLM API 密钥 | `app.config["LLM_API_KEY"] = "test-key"` | 必须在调用前设置，否则 LLM 路径被跳过 |

### 测试场景

| 测试方法 | 场景 | 验证点 |
|----------|------|--------|
| `test_falls_back_to_llm_when_multi_search_empty` | 多搜索无结果 + `sources` 含 `"llm"` + LLM 返回有效结果 | 调用 LLM，返回 LLM 生成的结果，`error` 为 None |
| `test_llm_returns_none` | LLM 调用失败返回 None | 返回空结果，`error` 包含 "unavailable" |
| `test_llm_returns_invalid_format` | LLM 返回非列表数据 | 返回空结果，`error` 包含 "format" |
| `test_llm_returns_empty_list` | LLM 返回空数组 | 返回空结果，`error` 为 None |
| `test_skips_llm_when_not_requested` | `sources` 不含 `"llm"` | 不调用 LLM，直接返回多搜索的空结果和 error |
| `test_skips_llm_when_multi_search_succeeds` | 多搜索已有结果 | 不调用 LLM，直接返回多搜索的结果 |

## 覆盖摘要

| 层次 | 测试文件 | 用例数 | 关键覆盖路径 |
|------|----------|--------|-------------|
| API 端点 | `test_search_api.py` | 14 | 内部搜索的参数解析/认证/边界，外部搜索的契约合规 |
| 服务层 — 多引擎搜索 | `test_multi_search_service.py` | 11 | SearXNG 调用、Sogou 合并、去重、空查询、错误降级 |
| 服务层 — LLM 兜底 | `test_external_search_llm_fallback.py` | 6 | 兜底触发条件、LLM 返回值处理、跳过条件 |

**当前未覆盖：**

- 语义向量检索路径（`EMBEDDING_ENABLED=true` 时的 `search_posters_by_vector`）
- 分页参数（`page` / `per_page`）的实际分页行为
- 知识节点的排序逻辑（当前固定按 `node_type` + `name` 排序）
